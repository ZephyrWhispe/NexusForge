# 13 自动化面板详细设计（B7 深化）

> 总纲：docs/impl/09 §7；对标：蓝本 §3.8 + n8n/Zapier/Power Automate/Quicker；状态：未开工。引擎内核远比 UI 强：重试(2,指数)+死信可查可重放（engine/lib.rs:5）、冷却+防自环风暴、and/or/not 嵌套条件（rule.rs:37-47）、WASM 插件沙箱（wasmtime+64MB/fuel）、standalone 预演通道（standalone.rs 已被 helper 用，lib.rs:67）。**UI 只暴露了引擎的三分之一。**

## 1. 现状问题

- **多动作静默丢数据（最高优先，数据完整性缺陷）**：表单只构造单动作 `then: [action]`（RulesPanel.tsx:195），编辑既有规则只读 `r.then[0]`（:219）——凡 then 长度 >1 的规则（API/插件/未来导入产生）经 UI 保存一次即**悄悄裁掉其余动作**；列表行还显示"动作 N 个"（:308），丢完自己都不承认。
- **IpcCommand 动作无表单**：后端 `Action::IpcCommand`（rule.rs:130）在 UI 动作下拉缺席（:100 仅 notify/open_url/publish/run_script）——最强动作类型（规则驱动任意模块命令）用户不可达。
- **when 只支持单叶子**：Expr 支持 and/or/not 递归，UI 只发一条 Leaf（:175-179），条件组合全靠手改 JSON 的概念根本不存在。
- **成功执行无痕**：只有死信页可看（:571），"规则触发过吗/为什么没触发"不可查——调试黑洞；事件本体也不可见（topic 全凭记忆手打，打错=规则永远静默不触发，无校验无下拉）。
- 无规则导入导出/复制/模板；冷却/防风暴参数埋在表单文本框无说明；插件能力声明（WasmCaps）不展示。

## 2. 子面板信息架构

| 子面板 | 类型 | 内容 |
|--------|------|------|
| 规则 | 清单 | 表：名称/触发摘要/动作数角标/启用/最近触发时间+结果/命中次数；批量启停、复制为新、导出/导入 JSON（导入跑 `validate()` rule.rs:162 拒绝非法，含 open_url scheme 白名单警告）|
| 编辑器 | 编辑 | 抽屉式：触发（事件 topic **下拉自目录**（见拓展①）/启动/定时 HH:MM + cron 挂 DeferredBadge A4）→ when **嵌套条件组构建器**（and/or/not 卡片递归+字段=点路径/比较/值三件套）→ **动作步骤列表**（多步骤增删排序，修复 :195/:219；ipc_command 表单=命令名下拉+参数 JSON 校验，红线：能力表沿用该窗 capability——规则不能越窗权）→ 冷却/重试策略（含默认值说明文案）|
| 执行历史 | 历史/日志 | 时间线：触发事件→when 求值轨迹（每个叶子实际取到的值）→各步骤结果/耗时/错误；过滤（规则/时间段/成败）；与死信互跳 |
| 死信 | 清单 | 现能力保留 + 按错误聚类 + 批量重放 + "带样本 payload 送执行历史干跑"（排障闭环）|
| 事件检查器 | 概览 | 调试页：实时滚动 nf:event 流（暂停/过滤/copy JSON）+ "用此事件测试规则 X"（**dry-run：全链求值但零副作用**）|
| 模板 | 清单 | 内置规则模板卡（例："剪贴板捕获密码形态 30s 后自动清空""低磁盘告警→通知+截图归档"）一键实例化进编辑器 |
| 插件 | 清单 | 现安装/移除保留 + 每插件 manifest 能力表（WasmCaps 逐项人话说明）+ "被哪些规则引用"反查（删插件前告知断链）|
| 设置 | 设置 | 全局暂停开关/默认冷却/风暴阈值/历史保留策略 |

## 4. 其他软件借鉴

- **n8n**：执行详情=节点级输入输出钻取（本仓映射为"步骤级 payload 快照"）；"从样例数据钉住"再编辑（试跑载荷直接当模板默认值）。
- **Zapier**：Filter 步骤=when 的产品语言（"只有当…才继续"）；延迟步骤（Wait）登记评估——需要引擎调度原语，防 scope 膨胀放 B8 提案。
- **Power Automate**：连接器的"我的规则用了它"计数（插件/命令反查引用）。
- **Quicker**：动作库共享的**心智**（导出 JSON 文件即分享载体，v1 不做在线市场）。
- **GitHub Actions**：`workflow_dispatch` 式手动触发按钮——规则卡上"立即执行"（跳过触发器直接跑 then，走完整重试链）。

## 5. 拓展设计（常人未思）

1. **事件目录**：宿主启动期枚举全仓 topic 常量（各模块 publish 点静态登记于 host-core 一张表）供下拉选择+每 topic 一行 payload 示例——根除"手打错 topic 规则永静默"这个自动化最大的沉默失败。
2. **求值轨迹**：when 不通过时历史里展示**每个叶子的实际取值**（`{payload.path=..., 期望 gt 5, 实得 3}`）——"为什么没触发"从玄学变一分钟排障。
3. **规则依赖图与拓扑序**：同 topic 多规则按声明序隐式执行是坑；显式 priority + "A 发布的 topic 被 B 消费"链路图 + 自环静态检测（发布 topic 出现在自身触发集→保存即警告，冷却是兜底不是设计）。
4. **红线映射器**：导入规则时展示"权限 diff"（此规则将可调用 vault_write/kvm_send…清单）并要求确认——规则=可编程攻击面，导入须像安装 APK 一样亮权限。
5. **成本保险丝**：单位时间动作执行总量熔断（默认值+触发即全局暂停规则引擎+托盘红点）——防"规则风暴把截图→OCR→上传自我放大"烧穿机器。
6. **草稿即沙箱**：编辑器"试跑"永不落库（不落历史表、不进冷却记录），与"立即执行"严格二分为两个按钮。

## 6. 验收点

- **多动作保存不丢失**回归：3 动作规则经编辑保存后 `then` 长度=3（vitest 表单往返 + Rust 侧 serde round-trip 双钉）；旧数据被裁切路径负例测试；
- and/or/not 构建器产物 = 后端 Expr 合法 JSON（golden 文件），深层嵌套（≥3 级）渲染与求值一致；
- dry-run 零副作用断言（无事件发布、无历史行、无冷却写入——三重负例）；
- ipc_command 动作：目标命令不在 main capability 即拒（沿用 D-28 ACL 机翻为人话错误）；导入权限 diff 必须确认（跳过=不导入）；
- 事件目录：新模块 publish 未登记 topic → 编译期/测试期红（host-core 表与 grep 实测一致性测试）；
- 执行历史保留策略生效（超 N 条截断）+ 死信重放成功入历史。
