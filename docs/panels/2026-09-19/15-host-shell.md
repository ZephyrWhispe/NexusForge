# 15 宿主壳详细设计（导航 / 设置中心 / 状态栏 / 快捷键 / 托盘 / 命令面板）

> 总纲：docs/impl/09 §3（B0 主体在此）+ B8 提案；对标：蓝本 §4.1-4.4 + PowerToys Run/uTools/Flow Launcher；状态：未开工。宿主壳是其余 14 档的**公共地基**：SUBNAV 机制、PANELS 注册表、设置中心 schema、DeferredBadge 全部在本档定义，各面板档直接引用不再各自发明。

## 1. 现状问题

- **14 层三元链渲染面板**：12 个模块面板硬编在 MainWorkbench 的双重三元里（:234-266），`screenshot`/`ocr` 明明在 MODULES 注册表（modules.ts:15-16）却因无组件落入"模块界面待实现"兜底——**注册与实现两张皮**正是本次用户报告的直接成因；惰性导入另列一摊（:11-22）。
- **设置中心写死剪切板**：`<SchemaForm moduleId="clipboard" />`（MainWorkbench.tsx:201）——任何模块的设置页都渲染 clipboard schema（全应用级 bug，B0 第一优先）。
- **SubNav 是私有组件**：190px 左栏硬编 CLIP_GROUPS（SubNav.tsx 全文），README §0.1 的通用化无处落脚。
- **侧边栏不可定制**：蓝本 §4.2"动态生成+用户可排序/隐藏"完全未做（顺序=MODULES 数组序，无用户偏好持久化）。
- **状态栏缺 3/4 字段**：蓝本 §4.1 承诺"模块状态｜网络状态｜剪贴板状态｜内核运行状态"——现只有模块健康点+错误角标（StatusBar.tsx:8-11），网络/剪贴板捕获态/代理内核态三格空缺。
- **快捷键无总览面**：HotkeyProvider 机制在（D-24 族），但用户看不到"谁占了哪组键、冲突与否、如何改"——蓝本 §4.4 给了默认键表而我们连现状态清单都没有。
- 通知只有右下角 toast+红点回放（stores/notifications），蓝本 §4.1 标题栏的"通知中心"（历史列表/已读）不存在。
- `host.module_state` 事件流健康，但**宿主设置（主题/Mica/开机自启/语言）散无归口**——目前无宿主自身的面板。

## 2. 子面板信息架构（宿主设置中心 = 第 15 个"模块"）

| 子面板 | 类型 | 内容 |
|--------|------|------|
| 外观 | 设置 | 主题（跟随/浅/深）、强调色（联动 `host_system_accent`）、Mica/透明、字号密度 |
| 导航 | 设置 | 侧边栏模块排序（拖拽）+显隐开关（写入 host_config，MODULES 保持唯一真相源，偏好只是投影）；"恢复默认" |
| 快捷键 | 清单+设置 | 全模块快捷键表（提供者/动作/当前绑定/冲突红标）+ 逐条改绑（录制控件）+ 一键重置；蓝本 §4.4 默认方案在此落地为初始值 |
| 通知中心 | 历史 | 持久化通知流（错误/模块状态变迁/同步与内核事件），已读/过滤/跳转来源模块；toast 只是它的瞬时投影 |
| 启动与托盘 | 设置 | 开机自启、启动行为（最小化到托盘/恢复窗口布局）、托盘菜单项显隐（消费 D-26 TrayProvider 聚合）|
| 关于与更新 | 概览 | 版本/updater 通道状态/诊断包导出（脱敏红线：不含凭据与日志明文，复用 D-19 错误通道数据）|

### 2.1 面板注册表（B0 硬交付）

```
PANELS: Record<ModuleId, ComponentLazy | { deferred: string }>   // deferred=指回 DECISIONS 的挂账文案
SUBNAV: Record<ModuleId, SubNavSection[]>
```

- MainWorkbench 渲染收敛为 `PANELS[active]` 一查到底（删 14 层三元）；MODULES 里每个 id **必须**在 PANELS 有键（组件或显式 deferred），vitest 断言全覆盖——今后任何模块不可能再"注册了却无界面"。
- 设置中心 SchemaForm 的 moduleId 跟随 active（修 :201）；各模块 config schema 由后端 settings_schema 通路供出（宿主/模块同一 schema 之家纪律，README §0.2）。
- `DeferredBadge`/`DataToolbar`/`EmptyState` 通用组件随本批落地（README §0.3）。

## 4. 其他软件借鉴

- **PowerToys（Settings 主页）**：模块=左导航卡片 + 每模块页右上角"启用"总开关（与本仓模块 Stopped 态对齐）；"键位冲突跨工具检测"是全 Windows 应用都欠的债（见拓展③）。
- **uTools/Quicker 插件面板**：模块商店心智的**本地版**——导航子面板预留"拓展（计划中）"灰位挂 DeferredBadge，防未来插件市场落地时再改 IA。
- **Flow Launcher/Wox**：全局搜索框=一切功能入口的替代形态（→拓展①）。
- **Windows 11 设置**：设置内搜索（设置页顶框，搜 schema 字段名跳锚点）——宿主设置中心字段变多后的第一件补课事。
- **VS Code 命令面板错误提示**：改绑快捷键时即时显示"已被 X 占用"而非保存后失败。

## 5. 拓展设计（常人未思）

1. **命令面板（Ctrl+Shift+Space）**：跨模块动作索引（"锁定密码库""新建日笔记""切换代理模式"…），数据源=各模块贡献的 `CommandPaletteProvider`（与 TrayProvider/HotkeyProvider 同族注册表）+ 拼音首字母匹配（本地词表，不联网）。与现有桌面启动器分工：启动器找**程序**，面板找**本应用的动作**。B0 先立 trait，实装在 B8 提案批准后。
2. **状态栏即告警轨**：四字段全部可点击直达对应模块子面板（代理内核红→代理"日志"，剪贴板暂停→剪切板"设置"）——状态栏从装饰变导航。
3. **快捷键冲突体检表**：注册时除 app 内冲突外，探测**系统级占用**（RegisterHotKey 试探回滚，成功=可注册的机器证据）并在总览表标灰——把用户装完软件才发现"Ctrl+Alt+K 已被微信吃掉"的挫败前移。
4. **通知深链**：通知中心每条带 `route=(moduleId, subnavId, entityId?)` 三元组——错误/冲突/告警可一键回到**产生它的那张列表的那一行**（实体高亮 2s），事件不再是死胡同。
5. **壳层回归金丝雀**：B0 的 MODULES/PANELS 全覆盖断言配一条"负例自检"测试（临时删一键必须红）——防止断言本身退化成永真（本仓 vitest 惯例：谓词自带可否例）。
6. **诊断模式**：关于页隐藏开关（连点版本号）→ 采集窗口列表/事件总线吞吐/最近错误环形缓冲到一份本地 JSON，供用户自查或随 issue 提交（导出前过拓展脱敏器：vault/剪贴板内容/代理节点串一律以哈希呈现）。

## 6. 验收点

- B0 核心负例：从 MODULES 数组临时移除 screenshot 的 PANELS 键 → vitest 全红（断言可失败自检）；设置中心对 5 个不同 active 模块渲染出 5 份不同 schema（ clipboard 独占时代的终结测试）；
- 状态栏四字段与后端事实一致性（停内核→内核格变灰；暂停捕获→剪贴板格出现暂停态）；
- 快捷键表：注册表实数=页面行数（漂移即红）；冲突行无法保存（负例）；系统占用探测有降级路径（探测失败≠崩溃）；
- 通知持久表重启后仍在；深链三元组跳转断言（含 entityId 高亮）；
- 侧边栏偏好读写 host_config，恢复默认后与 MODULES 原序一致；全部新组件过 D-18 基线（错误态含重试/查看日志）。

## 7. 排版方案与二审补充（2026-09-19 复审）

### 7.1 排版方案（宿主自身界面 + 壳层纪律）

- **主窗骨架**：标题栏 40px（通知铃铛+搜索钮右置）→ SubNav 190px → PanelHeader 48px → 内容单滚动 → Footer 状态栏 32px（00§1 的规格出处即本档）；状态栏四格从左到右=模块健康｜网络｜剪贴板｜内核，每格定宽且可点（§5-②）。
- **宿主设置中心**：与模块面板同骨架，左侧为其"导航"子面板的投影；每子面板一律 SwitchSetting 行制（00§6），分组序=外观（所见即所改）→导航→快捷键→通知→启动与托盘→关于。
- **快捷键表**：行 `[提供者模块][动作][当前绑定胶囊][冲突红标][改绑/重置]`；录制控件弹出后捕获按键序列，即时冲突回报（VS Code 借鉴：报错在录制态内联，不保存后失败）；表按模块分组折叠。
- **通知中心**：抽屉/独立页复用同一列表组件；行 `[色点：错误/状态/事件][标题+摘要][来源模块芯片][时间][已读]`，芯片点击=深链三元组跳转（§5-④）。
- **导航定制**：拖拽列表行 `[把手][图标+模块名][显隐 Switch]`，"恢复默认"在页 Footer 左端（非主按钮位）；被隐藏模块在 PANELS 仍注册，只是投影缺席（防"隐藏=卸载"误解）。
- **通用组件供给**：DeferredBadge/DataToolbar/EmptyState/PanelHeader/SwitchSetting/PathPicker 由本档 B0 批落地并配 vitest 组件基线（00§8 可判定化清单的宿主侧），各面板档引用不得各自造替换品。

### 7.2 配套功能缺口（二审新增）

1. **模块启停总开关升矩阵行**：§4 PowerToys"每模块页右上角启用开关"只写在借鉴段——升为 §3 矩阵第 10 行：每模块 PanelHeader 常驻"启用/停用"开关（映射模块 Stopped 态与 D-26 托盘聚合），导航子面板同步显示停用灰标；宿主壳必须提供这个统一形态而非各面板自理。
2. **首次启动导览**：00§7-④ 的落点在宿主——安装后首启的三步导览（全局热键录制→托盘行为确认→模块启用勾选），每步可跳过、设置"关于"页可重放；B0 面板补壳后用户面对的是 14 个新面孔，导览是配套的及格线而非锦上添花。
3. **全局配置包导出/导入**：00§7-③ 归口宿主"关于与更新"页——导出 host_config+各模块 settings schema 值+快捷偏好为单 JSON；红线机检：序列化器白名单制（凭据/剪切板内容/代理节点串/同步密钥结构上不可达），负例测试=往每模块 config 塞哨兵字符串后导出全文断言不含。
4. **设置内搜索**：宿主与模块设置页字段随 B0/B1 膨胀，Windows 11 式设置搜索（搜字段名/说明词→跳转子面板并高亮行）列 B1 尾批；词表=schema 字段标题与说明，零新数据源。
5. **语言与字体回退纪律**：i18n 维持不做（矩阵 #9），但壳层负责一条纪律——所有面向用户文案集中各模块 constants（现有惯例），且 UI 全用 Fluent 字体栈不硬编字体名（D-28 CSP 事故的兄弟面：字体硬编致渲染差异）。

### 7.3 锦上添花

1. **壳层自检页**：关于页"诊断"分区一行绿/红检查集（WebView2 版本/托盘注册/热键实绑数/总线吞吐）——D-28 之后装机问题的第一现场，数据全在现有通路。
2. **窗口布局恢复**：启动行为"恢复上次窗口布局"选项（多显示器拔插后窗口漂移是桌面应用经典抱怨），tauri window state 插件评估登记。
3. **托盘 tooltip 动态化**：状态摘要进托盘悬停文本（"NexusForge · 代理✓ 同步— 剪贴板⏸"），复用 D-26 set_title 通路（KVM 之外第二个常驻消费者，注意与 sys 托盘负载显示的互斥：同窗只有一族文案，优先级表定序）。
