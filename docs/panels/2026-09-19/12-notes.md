# 12 笔记与知识面板详细设计（B1 深化 + B7）

> 总纲：docs/impl/09 §7；对标：蓝本 §3.6 + Obsidian/Logseq/Zettlr/tldraw；状态：未开工。勘查修正一个预设：**notes 是接线最满的模块**——18 条 `notes_*` 命令（含双链/反链/卡片/复习/画板）全部被 NotesPanel 调用、零孤儿；它的"浅"不在通路，在**编辑器形态与信息架构**。

## 1. 现状问题

- **编辑器是 textarea**：正文编辑=裸 `<textarea>` + marked 预览开关（NotesPanel.tsx:650-656）——无 markdown 语法高亮、无 `[[` 自动补全（后端 `extract_links`/`resolve_link`（frontmatter.rs:96、library.rs:143）早已会解析与消歧，编辑时却全凭手打）、无大纲/斜杠命令/表格插入。
- **867 行单组件三 tab**：笔记/复习/画板挤在同一文件同一层 tab，子面板机制（README §0.1）未用；搜索=对 `notes_list` 结果的前端内存 filter（:536-537），**无内容级检索**（NoteIndex 无正文字段，index.rs 无 content/FTS）。
- **双链有骨无肉**：backlinks/links 后端齐（index.rs:193-233 `links_to/links_from/backlink_bases`），UI 只在阅读页列文字清单——无悬浮预览、无邻居图；**全局图谱无**（画板 canvas 是手摆的局部图，非库级自动图）。
- 无每日笔记/模板/孤儿-死链视图；剪贴板/截图与笔记的桥只有"手动粘贴"。
- 复习卡片功能齐（FSRS 味道的 grade，review.rs:20）但面板里是平铺队列——无统计、无按笔记聚合、无到期分布。

## 2. 子面板信息架构

| 子面板 | 类型 | 内容 |
|--------|------|------|
| 库 | 清单 | 树/列表双态（文件夹=路径前缀）、侧栏过滤器（标签/frontmatter 属性/修改时间段）、新建模板下拉、重命名（rename 已连带改引用）、**内容搜索**（新 `notes_search`：FTS5 索引正文+标签，snippet 高亮）|
| 编辑 | 编辑 | Monaco markdown（复用 editor 的 monaco/setup）+ 双栏实时预览 + `[[`/`#` 补全弹层（候选来自 notes_list universe）+ 大纲面板 + frontmatter 表单化编辑区 + 底部反链抽屉（含"以此创建笔记"）|
| 图谱 | 概览 | 全局力导向图（links 表直绘，万级节点先 2D canvas+分层加载，webgl 评估）+ 局部邻域图（当前笔记 N 跳）+ 节点色=标签/度=大小；孤儿笔记（零入零出）与**死链**（resolve 不中）红标 |
| 复习 | 清单 | 队列（现功能保留）+ 到期分布直方图 + 评分统计（保留率/日均）+ 按笔记聚合卡数 + 从编辑选区一键造卡 |
| 画板 | 编辑 | 现 canvas 能力升级：节点类型加"笔记引用/图片/URL"、框选多选、对齐吸附、导出 PNG；对齐 JSON Canvas 开放规范（偏离登记若改结构）|
| 每日 | 清单+编辑 | 日笔记流（模板生成+自动链向当日提及）、journal 时间线（按创建日聚合列表）|
| 设置 | 设置 | 库根目录（现 host_config）/重索引/新笔记模板/自动标题策略/附件目录策略 |

## 4. 其他软件借鉴

- **Obsidian**：反链面板的"未链接提及"（正文出现某笔记标题但未加链→一键成链）——纯前端可算（list+extract_links 已有原料）；图谱过滤器（按标签/路径显隐、深度滑杆）。
- **Logseq**：块级引用 `((block-id))` 登记 v1.1（需块锚点模型，改动索引结构，先不做）；journal 优先的交互心智（打开库即今日）。
- **Zettlr**：Zettelkasten 数字文件名 ID 选项（唯一且免重命名冲突）。
- **tldraw**：画板对齐参考线与键盘微操（方向键挪 1px/Shift 10px）。
- **Anki**：复习统计的"预测到期数"曲线（未来 7 天队列压力）——避免连击落灰后雪崩。

## 5. 拓展设计（常人未思）

1. **截图入资产流**：粘贴/拖入图片→自动落 `{root}/assets/{ts}.png` 并插入相对链接（截图模块"历史"右键"嵌入当前笔记"反向同理）——笔记里从此不出现裸路径与丢图；sync 覆盖 assets（B5 数据集含二进制附件走内容寻址，红线：单文件上限+超链不入 oplog 明文）。
2. **剪贴板→笔记收件箱**：剪切板收藏条目一键投递到 `_inbox.md`（clipboard×notes 桥），定期"整理收件箱"批量转正式笔记/卡片——采集与整理的分离心智。
3. **写作脉搏**：本地字数直方图（日新增字数/编辑热力日历，纯 appData 统计不上云）——知识工具的用户留存自我反馈。
4. **双链歧义守护**：`resolve_link` 重名消歧已存在，但编辑时补全弹层必须**显示解析后的完整路径**再插入（防"两个 项目计划.md"静默链错——数据完整性而非美观）。
5. **死链急救**：保存时 frontmatter/正文引用不中→行内波浪线+悬浮"创建此笔记/重命名以匹配"双动作——把图谱的红色告警前移到编辑时。
6. **模板即自动化**：模板库动作可挂 automation 规则（"每日 09:00 生成日笔记并同步到设备 B"）——notes 成为规则引擎的动作受害者而非特权者。

## 6. 验收点

- `notes_search`：CJK 混合语料正例 + 权限/capability 同步 + 索引与 `notes_sync` 一致性（改文件后搜索命中新内容）；
- 补全弹层：重名笔记插入路径断言（歧义负例）；反链"未链接提及"计算不误报代码块内文本；
- 图谱：千节点渲染帧率门槛（低端机 canvas 2D ≥30fps 人工证据档）+ 孤儿/死链集合与后端查询一致性；
- assets 落盘：路径逃逸负例（`../` 文件名消毒）；sync 附件超上限被拒且事件可见；
- 编辑器替换 textarea 后旧数据零丢失（升级前后文件字节级 diff=0，除非用户编辑）。
