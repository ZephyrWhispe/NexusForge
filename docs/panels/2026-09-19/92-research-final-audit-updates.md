## 1. 借鉴许可裁定（用户直令，先行登记）

- **软件不商用、仅个人使用**：对参考项目的代码**直接查阅、借鉴、移植（含 GPL/AGPL 项目）不设许可障碍**，此前调研期"仅理念借鉴、不抄实现"的保守口径由本裁定替换。
- 前置提醒（注意事项，非本次义务）：当前发布通道是 GitHub Release 出安装包——**一旦把含 GPL 组件衍生代码的构建产物分发给他人（含公开仓库挂出），即触发对应许可的源码/署名/传染性义务**。个人自用不触发；若将来公开分发，届时按组件逐笔补许可审查，本条为预登记哨兵。
- 因此本轮及后续实现批次的借鉴深度上调：内核更新器、geo 更新、订阅刷新等机制可对照 v2rayN（GPL-3.0）/ Clash Verge Rev（GPL-3.0）/ OpenClash（GPL-3.0）的既有实现直读移植，只按其数据面事实（端点、校验文件形态、目录约定）取齐，不引入其代码结构负担。

## 3. 代码级任务书标准（"要做到代码级"的落法）

用户要求方案文档达到"详细完整的计划任务书+验收标准"。事实核对：09 的 B0/B2 小节已有 文件:行、命令名、组件名、编号决策与验收清单——**距"代码级"差的是一致性的六栏粒度**。裁定标准（09 §2.5 全文），每个实施任务必须具备：

1. 目标锚点（文件:行或新建路径）；2. 接口形状（Rust/TS 函数/类型/command 签名字面）；3. 数据变更（migration 号+DDL+回填）；4. 门禁联动（capability 文件、schema 注册、安全负例名）；5. 回归清单（每任务正反例测试字面名）；6. 完成判据（机器可判定语句，不接受"体验良好"）。

流程不变（每批开工前先升级该批小节到六栏，与 plan-doc-first 同轨），本轮交付 **B9 全码级样例**（10 文档）+ **B0 按标准终审补齐**（09 §3 增补 T-B0-1..6 六栏表与 14 条测试字面名清单）。

## 4. 用户没点名但必须写进文档的注意事项（预登记）

1. **更新自举悖论**：代理内核的更新检查不得默认走"它自己拉起的代理"——默认直连，"复用系统代理"是显式 opt-in（网络故障时更新器不能一起死）。
2. **Windows 运行中 exe 不可覆盖**：替换必须停核→原子 rename→健康检查→失败回滚；服务形态（B2 decision-6）下"停核"涉及服务模式生命周期，属 D-13 提权边界，更新动作本身不提权，只做用户态目录内替换。
3. **镜像只搬字节，不改信任锚**：校验和/签名核对永远对官方源产物；镜像 URL 是用户数据不是内置常量（防供应链投毒面从官方漂移到野源）。
4. **zip-slip**：构件包解压只允许写入目标构件目录（路径规范化+前缀断言，can-fail 负例）。
5. **分流规则是文本，中毒即隐身**：规则集/订阅自动应用前做偏离度 diff（行数/域名变化率超阈值→暂停自动、转人工确认），与 D-29 已定的 Clash-YAML 中毒负例同族。
6. **降级与钉版本**：自动轨永不降级；用户显式降级需确认；构件可 pin 版本（防新版本破坏订阅兼容）。
7. **失败可见**：每次尝试落 `artifact_update_log`，活动页+通知深链呈现——静默失败是"看起来没更新"的新壳缺（00§4-② 的更新版）。
8. **更新窗口尊重使用**：auto 仅在空闲窗口执行（内核未运行或夜间）；正在代理流量时自动轨让路，手动轨弹确认（ShareX 借来的一条：不悄悄替换正在干活的组件）。
9. **Defender 误报**：GitHub 下载的内核二进制可能被杀软隔离——更新器检测"二进制在但启动失败=访问拒绝"时给引导文案（恢复+目录排除建议），**不自动改杀软设置**（D-13）。
10. **磁盘配额预检**：下载前查剩余空间（构件+备份 N-1 份+解压峰值三倍系数），不足则拒绝并说明。
11. **网络计量**：自动轨默认仅在非计量网络——**事实核正：本仓 win-integration 目前没有任何 metered/cost 感知实现（grep 零命中）**，动工时以 `windows` crate 调 `GetMeterNetworkCost` 新增一个小能力（列入 T-B9-5，纯查询零提权）；模型类大构件 auto 前二次确认。
12. **端点隔离**：应用本体更新（tauri updater，已上线）与构件更新器两套通道/表/命令互不引用，防一条通道被投毒连坐另一条。
13. **备份联动**：内核二进制与 geo 属可再生构件**不进** BackupStore（体积无意义），但 `artifact_meta`（策略、pin、TOFU 指纹）是用户配置，**进** app-settings 快照——TOFU 指纹若随备份回滚错配，下次更新必须重新人工核对（防"备份投毒"绕 pin）。
14. **速率与节流**：GitHub API 未认证 60 次/时——检查走 release.atom 或带 ETag 的条件请求，全局节流合并同 tick 检查；离线/失败退避加倍至 24h 封顶。
