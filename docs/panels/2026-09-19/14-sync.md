# 14 同步面板详细设计（B5：唯一"后端也要长"的面板）

> 总纲：docs/impl/09 §10；对标：蓝本 §3.2 同步章 + Syncthing/LocalSend；状态：未开工。定性结论先说：**sync 的薄不是没接线，而是后端可查询状态本身缺**——oplog 引擎比面板能展示的多得多，但 DTO 层只露了两个数字。relay 服务器/3-way 合并维持 §5 不做（本地优先、服务端不见明文）。

## 1. 现状问题

- **状态面贫瘠**：`sync_status` 仅 `{op_count, port}`（module.rs:313-316）——OpLog 里明明有 per-device cursor 表（oplog.rs:58、`cursor()/set_cursor()` :132-153，"只进不退"有单测 :230），**每个对端同到哪一刻看不见**。
- **冲突阅后即焚**：LWW 判负只发 `sync.conflict` 事件（module.rs:67-70），不落表——错过窗口即永久失踪；无冲突历史、无败方内容留存、无恢复路径（"自动解了但解掉了什么"不可审计）。
- **手动拨号**：`sync_now(device_id, addr)` 要求手输 `"192.168.1.10:49820"`（commands/sync.rs:28 注释自认）；PairedPeer 结构无地址字段（pairing.rs：device_id/name/fingerprint/pubkey_b64/paired_at），而 KVM 发现心跳本就携带 tcp_port——**在线设备与地址在运行时已知，UI 却要用户背 IP**。
- **数据集硬锁笔记**：`const ENTITY: &str = "note"`（module.rs:39），record_change 单点写死；面板文案"数据集 v1=笔记库"诚实，但无注册机制，加一个数据集=改一处常量冒一处风险。
- SyncPanel 178 行单页：设备列表+状态两个数+"输地址点同步"——无进度、无历史、无字段级详情。
- 无自动同步策略（编辑保存后何时该同步全靠人想得起）。

## 2. 子面板信息架构

| 子面板 | 类型 | 内容 |
|--------|------|------|
| 概览 | 概览 | 本机身份（设备名/指纹短串）、监听端口、在线设备灯泡（发现缓存驱动：设备+IP:port+最后心跳）、最近一次同步摘要卡（applied/lost/conflicts 三色）、**手动"立即全部同步"**+自动同步开关（变更后 N 分钟静默期触发）|
| 设备 | 清单 | 配对设备表：名称/指纹/`已同到 cursor`（最后同步 ts 人话化+落后 op 数=对端 max_ts−cursor）/上次结果/删除同步关系（确认词；只断同步**不动 KVM 配对**，文案写明）|
| 数据集 | 清单+设置 | 数据集注册表（笔记✅；收藏分组/片段库/看板列=白名单候选，逐项开关"参与同步"；**密码库永不出现在此页**——红线见 §5）；每数据集：op 计数/最后变更时间/体积 |
| 冲突 | 历史/日志 | 冲突史表（新 SQLite 表落 appData：时间/实体/键/胜方设备/败方 ts）→ 行内"查看败方内容快照/以我为准回滚"（快照=判负时的加密 blob 留存，保留策略可配）|
| 活动 | 历史/日志 | 每轮同步流水（对端/推拉条数/字节/耗时/错误），失败重试可见 |
| 设置 | 设置 | 静默期分钟数/带宽启发式限制（局域网默认放开，登记评估）/冲突快照保留天数/发现端口（49820 与 KVM 49800/49801 族谱说明）|

## 4. 其他软件借鉴

- **Syncthing**：设备页"落后 N 项"的 lag 表达（cursor vs 对端最新 ts 差）；忽略模式的 glob 语义与例外前缀 `!`；"仅在我要求时共享/接收"的单向位（数据集开关升级为 push/pull 双闸——设备 A 推给 B 但不同拉，出差场景刚需）。
- **LocalSend**：传输即会话、无长期配置的轻心智→概览页"一次性发一批给在线设备"（复用 sync transport 走 KVM send_file 通路，评估后若重则挪 B8 提案）。
- **Resilio/Apple 同步**：变更静默期合并窗口（连续编辑不产生 100 条 op 风暴——record_change 侧 debounce）。
- **Git 托管页**：活动流水的"提交图"感（每轮同步一行，点开看 op 明细）。

## 5. 拓展设计（常人未思）

1. **红线机器化**：数据集注册表 schema 层面**不存在 vault 枚举位**（编译期白名单常量数组，加一行评审纪律测试：断言 `"vault"` 不在合法 entity 集——把"密码库永不流动"从文案升格为可否例）。
2. **cursor 落后警报**：lag 超阈值（如 7 天未同步）→ 托盘黄点+概览红条，附"上次成功后本地已产生 N 条未出账变更"——把"忘同步"从事故后知变事前可见。
3. **冲突预演**：设备页"检查更新"干跑：交换 hello+cursor 不落库不 apply，仅报"将拉 N 条/将推 M 条/预计冲突 K 处"——先看清再按同步。
4. **快照解密边界**：败方冲突快照仅在**本机解锁状态可解密查看**，导出功能不存在（防止 LWW 败方副本成为新泄漏面——E2E 的另一端还是自己，但 UI 必须假设肩窥）。
5. **设备指纹变更冻结**：对端 pubkey 与 PairedPeer.fingerprint 不符 → 该设备自动降级为"已暂停"红标，需去 KVM 模块重新配对确认（中间人防御的同步侧闭环）。
6. **时间卫生**：LWW 信任 ts，跨机时钟偏移是隐性错判根因——每轮同步记录两机时钟差估计进活动流水，偏差 >60s 时概览挂提示（不修 LWW，只让用户知道自己在什么地基上）。

## 6. 验收点

- `sync_status` 新 DTO 断言含每对端 cursor 与 lag（单测构造两设备异步场景）；冲突表落库+重启后可查（事件即焚时代终结的回归）；
- 地址自动补全：发现缓存为空时回退手输（负例：离线设备不出现幻影地址）；
- 数据集泛化：新增第二实体（收藏分组）不改 engine/transport 一行（架构验收）；`"vault"` 不在 entity 白名单的可否例测试；
- 设备指纹不符 → 该 peer 同步被拒 + 红标（安全负例）；cursor"只进不退"在重放攻击式旧 ts 下不破（oplog.rs:230 语义的 DTO 层延伸）；
- 快照仅解锁可解密：锁库状态请求冲突快照内容 → 拒绝（红线负例）；
- 新命令/字段变更同步 permissions+capability（D-28 完备性测试兜底）。

## 7. 排版方案与二审补充（2026-09-19 复审）

### 7.1 排版方案（逐子面板）

- **概览**：四卡网格（本机身份/监听/在线设备/最近同步），最近同步卡=applied绿·lost灰·conflicts红三色计数，点击各段跳对应子面板预过滤；"立即全部同步"主按钮在页右上（PanelHeader 右端，00§3 恒最右），自动同步开关紧随其下（开则显示"静默期 N 分钟"内联字段）。
- **设备**：表行 `[灯泡：在线+IP:port/离线最后心跳][名称+指纹短串][cursor 进度：已同到 ts+落后 N 项][上次结果色点][检查更新/删除…]`；落后 N 项>0 黄字（§5-② 警报的表格形态）；删除在 destructive 分隔线下+确认词，确认框内写明"不影响键鼠模块配对"（§2 文案的强制出现位）。
- **数据集**：注册表行 `[实体名人话][参与同步 Switch][push/pull 双闸][op 数][体积][最后变更]`；vault 不渲染（§5-① 红线的 UI 表达——不是灰行，是不存在）。
- **冲突**：历史表 `[时间][实体/键][胜方设备][败方 ts][查看快照/以我为准回滚]`；快照查看仅在解锁态可点，锁定时禁用+tooltip 原因（00§4-④ 与 §5-④ 边界的 UI 化）。
- **活动**：流水行 `[对端][推 n/拉 m][字节][耗时][错误Badge]`，展开行=op 明细（类型/键/ts/两机时钟差估计，§5-⑥ 数据落点）。
- **设置**：分组序=自动同步策略（前置）→冲突快照保留→发现与端口（49820 与 KVM 族谱说明卡）→带宽（登记态挂 DeferredBadge）。

### 7.2 配套功能缺口（二审新增）

1. **设备备注名**：PairedPeer 已有 device_name（对端自报），配套补**本机侧别名**字段（家里台式机 vs 同事的笔记本，指纹短串认人太累）；改名的同时两机同步可见性登记（仅本地备注则文案明说"仅你可见"，禁歧义）。
2. **首包体量预估**：新数据集首次参与同步=全量 op 回放，静默开闸可能灌几百 MB——数据集开关从 Switch 升级为"开→先报将推 N 条/约 X MB→确认"（复用 §5-③ 冲突预演的 hello+cursor 干跑通路，一鱼两吃）。
3. **同步关系与 KVM 配对的关系文案**：两模块共享信任根（pubkey/fingerprint），设备页与 06-kvm 设备页互挂一行说明+深链，否则用户在两处看到"同一台设备"两个开关无从对账。
4. **未出账变更计数**：§5-② lag 警报的本地侧镜像——概览显示"本机自上次成功后已产生 N 条待推变更"（oplog 本地 max_ts−自身已推 cursor 可算，登记勘查）；只有对端 lag 没有本地 pending 是半边透明。
5. **发现端口冲突自检**：49820 被占的降级路径要有机检面——监听失败时概览红条+活动页首行错误，而不是静默"看起来没设备"（sync 版 00§4-②）。

### 7.3 锦上添花

1. **"这台设备在同步什么"卡**：设备行展开=按数据集分列的该对端 push/pull 实况——矩阵式共享配置在 Syncthing 里是表格地狱，此处收成卡片。
2. **同步节律迷你sparkline**：概览 7 天活动密度条（数据即活动流水聚合）——"我到底多久没同步了"的直觉化。
3. **一键全部检查更新**：设备页工具条按钮，串行对在线设备跑预演并汇总"共将拉 N 条"——先看清再按同步（§5-③ 的批量化）。
