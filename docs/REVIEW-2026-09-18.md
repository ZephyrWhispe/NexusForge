### 1.1 测试红灯根因（本次审查新发现）

失败用例为 `conpty_min_echocon_reference`（[crates/win-integration/tests/conpty_min.rs:154](../crates/win-integration/tests/conpty_min.rs#L154)），硬断言 ConPTY 渲染流包含 pause 提示。该文件是 **ConPTY 分诊遗留的诊断探针且未提交**，但位于 `tests/` 目录故默认参与 `cargo test`；同时它在 [:33](../crates/win-integration/tests/conpty_min.rs#L33) 调用 `FreeConsole()` 摘除调用方控制台，会污染运行它的终端与同进程后续测试。

**结论**：已提交代码的测试是绿的，但"一条命令验证全绿"当前不成立，且 CI 若建在当前工作区上会直接红灯。处置见 [DECISIONS D-20](./DECISIONS.md#d-20-conpty-诊断探针与验收门禁治理)。

## 6. 值得肯定

- **架构收敛是真的**：`windows` crate 实测**只出现在** [win-integration/Cargo.toml](../crates/win-integration/Cargo.toml#L16-L75)——O2 的"依赖收敛"达标；port trait 非装饰，已验证 11+ 个端口被模块真实消费。
- **关键算法真实且质量高**：Windows.Media.Ocr 真 WinRT 调用；kvm 的 X25519 + ChaCha20 帧协议、分块 SHA256 校验与断点续传；vault 的 Argon2id + AES-256-GCM + zeroize；automation 的 wasmtime fuel 与内存限额；SQL 全参数化 + 强制 LIMIT + FTS 转义。
- **无跨模块读表**：sync 通过 `SnapshotSource` trait 抽象访问业务数据（[sync-core/engine.rs:15-19](../crates/sync-core/src/engine.rs#L15-L19)）。
- **无桩函数残留**：全仓 `todo!`/`unimplemented!` 命中 0。
- **前端类型纪律优秀**：`strict` + `tsc` 零错误 + **0 处 `any`/`@ts-ignore`** + 仅 6 处非空断言；IPC DTO 与 Rust 侧对齐且有 `parseAppError` 运行时形状校验。
- **代码分割正确**：11 个面板 + 全部子窗口 `lazy()`，首屏 `index` 仅 501KB；`StrictMode` 双挂载竞态有 `cancelled` 回收（[overlayController.ts:24-28](../src/windows/overlayController.ts#L24-L28)）；覆盖层用物理像素且内容就绪才 `show()`。
- **错误码是真实常量**（[host-core/codes.rs:10-27](../crates/host-core/src/codes.rs#L10-L27)）；注册表确有 panic 隔离 + 崩溃事件 + Error 态重启，且有对应测试。
- **开发者诚实记录偏离**：多处注释/文档主动标注"后续里程碑""偏离"，显著降低审查成本，应保持。
